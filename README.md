# goal-lock

> 一套让 AI Agent 在多轮会话里**不把「测试」漂移到「产出」**的规则文本。

不是代码，不是技能包，是一份可以直接粘进 `AGENTS.md` / `CLAUDE.md` / system prompt 的规则。

**状态：`v0.1.0 draft`**。当前验证样本 = 1（一个模型、一个 harness、一个任务）。本仓库**不宣称**已证明解决 Agent 目标漂移；它公开的是「一个可复现的失效案例 → 规则 → 验证」这条证据链。

---

## 30 秒接入

1. 把 `core/inspect-task-mode.md` 的内容贴进你的 Agent 规则文件。
2. 可选：把 `goal-lock.md` 的多层级目标树与尾注模板一起贴进去。
3. 判断生效的标准：任务被判成「检验意图」后，后续轮次里 Agent 不再主动提议换工具、不再把「要不要切换渠道」做成选项、每轮结尾能报出「一级目标 → 子任务」的多层级状态。

无需安装、无需 API key、无需联网。

---

## 这份规则解决什么

一个真实失效案例（已脱敏）：

> 会话目标行写着「测 A 的生图质量」，并且明确点了一个参照组 B。
> 中途 Agent 却调用了环境里默认的出图工具产出一张图，把它当作测试结论交付，
> 随后又自写「否则就此结项」，把一句自己写的话当成已生效的前提。

逐层归因后得到四类根因：① 「测试」被误判成「生图」；② 自写的「结项」被当作授权；③ 默认工具钩子接管了被测通道；④ 单样本产出冒充了比较级目标。

规则因此分成两层：

| 文件 | 管什么 | 信源角色 |
|---|---|---|
| `core/inspect-task-mode.md` | 解析「用 A 执行 T」时，判**检验意图（α）**还是**工具意图（β）**；α 下禁换工具、禁把切换做成选项 | **唯一权威核心** |
| `goal-lock.md` | 多轮里怎么不把「测试身份」弄丢：目标树分层、父变更子作废、临时目标自动回落、尾注状态快照、弹窗阈值 | 推导件，只写指针，**不复制 core 的 §1** |

改 α/β 判据只改 `core/`；`goal-lock.md` 里只有链接。这正是为了避免两份文本都自称权威而漂移。

## 边界（请连同规则一起读）

- **样本 = 1**：「每轮开头先读锁定态」这条是否对别的模型 / 别的 harness 生效，**未验证**。
- **规则文本很难用版权保护思想**：别人抄进自己的 prompt 连署名都未必保得住。按「建标准 / 影响力」定心态，别按「控分发」。
- **`core/` 当前是恢复版，不是作者逐字原稿**：文件头已如实标注来源与待补录处（§2 回复范式）。作者补录逐字原稿后以原稿整体替换，且只改这一处。
- 本仓库不含任何密钥、机器相关的绝对路径、内部判例编号或商业化决策。
