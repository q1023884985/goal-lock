# 验收裁决即关闭一级目标；「沿用锁定渠道」只在测试进行中成立

> 来源：precedent p064 · 状态：`v0.1.0 draft`

## 判据

用户给出验收裁决（「X 合格」「通过」「可以结项」「请导出报告」）时：

1. **一级目标当场标「已验收闭环（已完成）」**，不是把裁决只当报告里的一条「用户口述」数据来源存档。用户口述既是报告的事实来源，**同时也是会话状态变更指令**（用户已声明的前提是一票否决级约束）。

2. **「锁定态下用户给新 T 但未点渠道 → 沿用已锁定渠道，作为追加用例」有隐含前提：测试仍在进行中**。一级已验收后该前提消失；此后用户发起的任何新话题不得默认判为旧目标的追加用例，否则就是在已闭环的父目标下派生悬挂子任务（父变更 → 子作废）。

3. 若要测新的条件（如「无代理可达性」），那是**新的独立任务**，由用户明确重新发起；Agent 不主动把它挂回旧目标，也不弹「要不要开新任务」选项。

4. **尾注自检**：用户质问「还没结束吗」时，先查 📍 阶段里一级是否标了「已完成」、有无残留「进行中 / 阻塞」的悬挂子任务；🎯 目标行是一级标识符、不是进度条，但阶段行必须如实反映验收态。

5. **🎯 行闭环处置**：一级已验收闭环时，🎯 目标行写「已验收闭环：<原一级名称>」（如 `已验收闭环：测 yangvip TT Image 生图质量`），**不得复述为当前进行中的目标**；📍 阶段只写当前活跃路径，不含历史一级。

## 指纹实例

- **2026-11-08**：用户「yangvip TT Image 合格，可用于其他项目，请导出报告」→ Agent 导出了验证报告，把裁决记为报告「用户口述」，但尾注 📍 阶段里一级仍只标「（锁定）」、未标已验收；随后用户问「还没测试无网络代理情况是不是通的」，Agent 判成旧目标「追加用例」并动手准备探测，用户随即质问「目标还没结束吗？我前面不说过了合格并导出报告了吗？」。根因 `[指令理解偏差]`：验收裁决只被当数据、没被当状态变更，且把「沿用锁定渠道」套用到已结束的测试。探测**未执行**（未发请求、未扣费、未落盘脚本或读数）。
