# 失效 → 修复（脱敏片段）

> 已去除全部平台名、机器路径、密钥与内部编号。仅示意规则如何改变行为。

## 漂移

用户：测一下 A 通道的生图质量，拿 B 做参照组就行，做一张对比就好。

Agent（第 2 轮）：我用环境里默认的出图工具做了一张图，效果如下…… 这图做得没问题。
Agent（第 3 轮）：既然图已出，否则就此结项。

问题：

1. 目标是「测 A」，产出却来自环境里的默认工具 —— 被测通道根本没上场。
2. 「参照组 B」被抬进了一级目标，而它其实只是实现方案。
3. 自写的「结项」被当成已生效的前提。
4. 单张产出冒充了「对比」这个比较级目标。

## 修复后

用户：执行。

Agent（第 1 轮）：按一级目标，先核实 A 通道自己的入口（零成本、只读），
                  再提交一组 paired run；被测通道必须是 A，付费前把成本报给你。
Agent（交付）：A 走 A 站点自己的同源入口、B 走参照组，两侧同 prompt、
               各提交一次、无重试；并排图 + 精确读数 + 单样本边界声明。

改变行为的不是一句「别换工具」，而是：

- core §1 把任务判成 α 检验意图，动作集合里只允许调用 A（+ 用户点名的参照组）；
- core §1 禁止把「调用 B」作为可选项递给用户，连「下一步 / 弹框选项」也算；
- 本扩展件的尾注每轮把「一级 → 实现方案 → 子任务」重新报一遍，漂移在下一轮立刻可见。
